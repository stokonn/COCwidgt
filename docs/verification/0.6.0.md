# COCwidgt 0.6.0 verification record

This document records the verification contract for the published v0.6.0 prerelease. It distinguishes automated release checks from manual device acceptance.

## Automated release gate

The version-specific workflow is `.github/workflows/release-v0.6.0.yml`. Its release job is configured to:

- Run `testDebugUnitTest` and `lintDebug`.
- Build debug and release APK variants.
- Check that the release APK exists and is a valid ZIP archive.
- Verify ZIP alignment.
- Verify the APK signature and compare its signer certificate SHA-256 fingerprint with the expected original release certificate.
- Check package name, version code and version name.
- Generate `SHA256SUMS.txt` for `cocw0.6.0.apk`.
- Upload the APK and checksum to the GitHub prerelease, then download the published APK and compare it with the build output.

The expected certificate fingerprint is public verification metadata embedded in the workflow; it is not a signing secret.

## Standard pull-request CI

The general Android CI workflow runs on pull requests and pushes to `main`. It executes the debug build, unit tests and lint, then uploads the debug APK as an Actions artifact.

## Manual acceptance areas

Automated compilation and unit tests cannot fully validate Android launcher behavior. A device acceptance pass should record:

| Area | What to check |
| --- | --- |
| Installation/update | Install the APK and verify update behavior from the previous compatible release. |
| JSON import | Import a current village export and confirm the Player Tag and visible upgrade rows. |
| Multiple accounts | Add, rename, switch and remove accounts; confirm village data stays associated with the correct tag. |
| Migration | Upgrade an installation containing legacy single-account data and confirm that the account is available after migration. |
| Per-widget selection | Add multiple widget instances and assign different accounts. |
| Widget sizing | Check compact, medium and large sizes on the target launcher. |
| Refresh | Confirm countdown presentation updates according to Android scheduling behavior. |
| Offline use | Confirm imported village data remains visible without a successful profile lookup. |

## Evidence boundaries

- A passing CI workflow is evidence of the checks that workflow actually executes; it is not evidence of physical-device acceptance.
- The repository does not claim a complete launcher/device matrix from CI.
- The Town Hall 19 variant export representation remains a known unvalidated area, as noted in the v0.6.0 release notes.
- When adding manual results, include device model, Android version, launcher, app version, test date and outcome. Do not label a check as passed without recorded evidence.
