## Documentation principles

- The source code and automated tests are authoritative for implementation details.
- Release notes describe a specific published version; they are not a promise that every planned feature exists.
- Device and launcher behavior can vary. A CI build is not a substitute for physical-device testing.
- Legal notices and third-party asset provenance are maintained in the repository root and under `LICENSES/`.

For repository-wide contribution and security information, see [CONTRIBUTING.md](../CONTRIBUTING.md) and [SECURITY.md](../SECURITY.md).
